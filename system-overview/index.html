VATP IPCEI-CIS · HVAC AI Platform

System Overview

One page on how the platform hangs together. Smart HVAC devices in the VATP buildings sit on a private network, and an on-site server in the same building runs the whole platform: a gateway polls every device, delivers a single authenticated data feed to the web application, which stores everything in a time-series database and serves dashboards, alerts and AI insights. The same gateway will carry AI control commands back to the devices once that path is enabled. No device ever talks to the web app directly.

~150 live data points production: https://ipcei.vatp.lv

Public surface

  • One domain: ipcei.vatp.lv — web UI and REST APIs behind login (role-based access), served from the on-site server.
  • Nothing else is reachable from the internet — devices and server share a private network inside the building.

Data timing

  • Poll rates by protocol: valves (BACnet) 40 s · meters (HTTP) 60 s · AHUs (Modbus) 10 min · heat pumps (Luxtronik) 15 min.
  • Storage is capped at one reading per sensor per 10 minutes — dashboards move in 10-minute steps, not real time.
  • If a device stops reporting, the platform raises an offline alert.

Scope & direction

  • Today the platform is monitoring & analytics — dashboards, per-machine energy breakdown, alerting, comfort scores, ML advisories.
  • Next: AI-driven control. The ML models will send control commands to the devices, dispatched through the web app and gateway over the same connections shown above.
  • That control path is built into the architecture but not yet enabled — until it is, the platform reads and recommends, it does not actuate.
